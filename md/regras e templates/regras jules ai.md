## 1. 🛠️ Meta-Prompts (Otimização)

*Use para preparar o terreno antes de qualquer tarefa complexa.*

### 🚀 O Otimizador Recursivo (God Mode)

*Transforma uma ideia ruim em uma especificação de engenharia.*

```text
Atue como Principal Prompt Engineer e Arquiteto de Sistemas.
Analise minha solicitação bruta: "[INSERIR SUA IDEIA AQUI]"

Sua missão:
1. Identificar ambiguidades, falhas lógicas e falta de restrições.
2. Reescrever minha solicitação seguindo o framework "R-C-T-C" (Role, Context, Task, Constraints).
3. Aplicar técnicas de Chain-of-Thought para garantir raciocínio profundo.

Saída esperada: Apenas o PROMPT FINAL REFINADO pronto para eu copiar e usar.
```

### 🧠 Compactador de Contexto (Save Game)

*Para "salvar" o estado da conversa e continuar em outro chat.*

```text
Atue como Especialista em Compressão de Informação.
Realize uma "Compressão Semântica Lossless" de toda a nossa conversa até agora.
Preserve:
1. Decisões Arquiteturais e Stack Tecnológica.
2. Regras de Negócio e Restrições definidas.
3. Estrutura de arquivos atual e Pendências (To-Do).

Gere um "Token de Contexto" (texto denso) que eu possa colar em uma nova sessão para restaurar 100% do entendimento do projeto sem alucinações.
```

## 2. 🏗️ Arquitetura & Systems Design

*Definições estruturais de alto nível.*

### 🏛️ Gênese de Arquitetura (Microservices/Monolith)

*Design de sistemas robustos.*

```text
Atue como Arquiteto de Software Sênior (ex-AWS/Google).
Preciso desenhar a arquitetura para: [DESCREVER SISTEMA/PRODUTO].

Requisitos:
1. Defina a Stack ideal (Frontend, Backend, DB, Infra) com justificativa técnica (Trade-offs).
2. Desenhe o Diagrama de Fluxo de Dados (Mermaid) crítico.
3. Estratégia de Escalabilidade: Como lidar com 10k req/s? (Caching, Sharding, Load Balancing).
4. Modele as Entidades principais e seus relacionamentos (ERD Teórico).

Restrição: Priorize Baixa Latência e Custo Efetivo.
```

### 💾 Modelagem de Banco de Dados (SQL/NoSQL)

*Criação de schemas eficientes.*

```text
Atue como DBA Especialista.
Projete o Schema para a funcionalidade: [DESCRIÇÃO].
Banco de Dados alvo: [PostgreSQL / MongoDB / Redis].

Entregáveis:
1. DDL (Data Definition Language) completo e otimizado.
2. Estratégia de Índices (quais índices criar e por quê?).
3. Análise de Normalização (3NF) vs Desnormalização (Performance).
4. Queries de Exemplo para as operações mais frequentes (Hot Paths).
```

## 3. 💻 Full-Stack Coding (Development)

*Geração de código de produção.*

### ✨ Componente "First-Class" (React/Vue)

*Criação de UI robusta e acessível.*

```text
Atue como Arquiteto Frontend & Especialista em A11y (WCAG).
Crie o componente: [NOME DO COMPONENTE].
Stack: React, TypeScript, TailwindCSS.

Diretrizes Estritas:
1. Pattern: Use Polimorfismo ('as' prop) ou Compound Components.
2. Estado: Evite 'useEffect' chains. Use Reducers ou XState se complexo.
3. Acessibilidade: Navegável por teclado, ARIA labels corretos, foco visível.
4. Tipo: 'Strict Mode'. Sem 'any'. Interfaces explícitas com JSDoc.

Saída: Código completo + 3 Exemplos de uso (Simples, Variante, Erro).
```

### ⚙️ API Controller Blindado (Backend)

*Lógica de servidor segura.*

```text
Atue como Backend Security Engineer.
Implemente o Endpoint: [MÉTODO] [ROTA].
Stack: [Node.js/Python].

Camadas de Defesa Obrigatórias:
1. Validação de Input (Zod/Pydantic): Rejeite tudo que não for estritamente esperado (Whitelist).
2. Tratamento de Erro: Não vaze Stack Traces. Use HTTP Codes semânticos.
3. Database: Use Prepared Statements/ORM para prevenir SQL Injection.
4. Performance: Early Return e complexidade ciclomática baixa.

Entregável: Código do Controller + Schema de Validação.
```

### ♻️ Refatoração Legado (The Strangler)

*Melhoria de código ruim.*

```text
Atue como Staff Engineer focado em Clean Code.
Analise o código abaixo:
[COLAR CÓDIGO AQUI]

Missão:
1. Identifique "Code Smells" (Acoplamento, Funções Longas, Nomes Mágicos).
2. Identifique Riscos de Segurança e Performance (Big O).
3. REFATORE para um padrão moderno, modular e testável (SOLID/DRY).
4. Explique o "Porquê" de cada mudança crítica.
```

## 4. 🎨 Frontend, UI & Vibecoding

*Estética, Animação e CSS de ponta.*

### 🔮 O "Glassmorphism" Matemático

*Estilo visual premium.*

```text
Atue como UI Engineer especialista em Física Óptica.
Crie o CSS para um Card com estética "Premium Glassmorphism".

Regras de Física Visual:
1. Background: Gradiente sutil + Blur agressivo (backdrop-filter).
2. Bordas: Translúcidas (White alpha low opacity) para simular refração de luz.
3. Sombras: Multi-layer shadows coloridas (não preto puro) para profundidade difusa.
4. Textura: Adicione noise.png com blend-mode overlay para realismo.
```

### 🎬 Coreografia de Micro-Interações

*Animações que parecem vivas.*

```text
Atue como Motion Designer (Framer Motion / CSS Master).
Anime o componente: [DESCRIÇÃO].

Leis do Motion:
1. NUNCA use 'linear'. Use curvas Bézier customizadas (ex: cubic-bezier(0.2, 0.8, 0.2, 1)).
2. Feedback Físico: Scale down no click (0.98), Lift up no hover.
3. Sequenciamento: Entrada em 'Stagger' (cascada) para listas.
4. Performance: Use apenas Transform e Opacity. Paint properties proibidas.

Gere o código CSS/JS da animação.
```

## 5. 📊 Data Science & Estocástica

*Análise estatística para loterias e dados financeiros.*

### 🎲 O Analista Estocástico (Lotto/Finance)

*Padrões em caos.*

```text
Atue como PhD em Estatística e Data Scientist.
Contexto: Análise de [Loterica/Financeira] baseada em histórico CSV.

Tarefa:
1. Carregue os dados e realize Limpeza (Handling Nulls/Outliers).
2. Execute Testes de Aleatoriedade (Kolmogorov-Smirnov, Chi-Square) para validar integridade.
3. Análise de Frequência, Atrasos e Correlação (Heatmap).
4. Gere um Modelo Preditivo Simples (Monte Carlo ou Regressão) para projetar cenários futuros.
5. Identifique anomalias que desviem mais de 2 Desvios Padrão da média.

Saída: Código Python (Pandas/Scipy) documentado.
```

### 📈 Interpretação de Dados (Insights)

*Transformar números em decisão.*

```text
Atue como Business Intelligence Analyst.
Analise este Dataset/Resultado: [COLAR DADOS].

Missão:
1. Identifique as 3 Tendências Macros mais fortes.
2. Identifique os "Outliers" (valores extremos) e hipóteses para sua ocorrência.
3. Responda: Se eu tiver que apostar em um padrão para o próximo ciclo, qual tem a maior esperança matemática?
```

## 6. 🛡️ Segurança & QA (Destroyer)

*Quebre para consertar.*

### 💣 O Advogado do Diabo (Auditoria)

*Crítica destrutiva de código.*

```text
Atue como Security Researcher (Red Team).
Audite o seguinte código/arquitetura: [DESCRIÇÃO/CÓDIGO].

Modo: "Ruthless Critique".
1. Encontre vetores de ataque (XSS, Injection, Broken Auth).
2. Encontre falhas lógicas que permitam abuso do sistema.
3. Critique a complexidade desnecessária.

Saída: Relatório de Vulnerabilidades (Rankeado por Risco Crítico).
```

### 🧪 Gerador de Testes Unitários (Jest/Pytest)

*Cobertura total.*

```text
Atue como QA Automation Engineer.
Escreva testes para a função: [NOME/CÓDIGO].

Estratégia de Teste:
1. Caminho Feliz (Standard Success).
2. Edge Cases (Inputs nulos, arrays vazios, caracteres estranhos).
3. Error Handling (Simule falhas de dependência/rede).
4. Se usar Datas/Random, faça Mock para determinismo.

Saída: Arquivo de teste completo.
```

## 7. 💼 Estratégia de Produto

*Negócios e Gestão.*

### 📉 Negociação de Escopo (Scope Creep)

*Dizer "não" profissionalmente.*

```text
Atue como Product Manager Sênior e Diplomata.
Escreva uma resposta para o cliente que pediu: [DESCRIÇÃO DO PEDIDO FORA DO ESCOPO].

Objetivo:
1. Validar a empolgação do cliente ("Ótima ideia!").
2. Expor a realidade ("Isso impacta a entrega atual em X dias").
3. Oferecer alternativas ("Podemos adicionar ao Backlog da V2" ou "Podemos trocar por outra feature de mesmo tamanho").

Tom: Firme, Profissional e Orientado a Solução.
```

### 📝 Post-Mortem de Incidente

*Explicação de falhas.*

```text
Atue como Site Reliability Engineer (SRE).
Escreva um Post-Mortem para o incidente: [O QUE ACONTECEU].

Estrutura:
1. Resumo Executivo (Para a Diretoria).
2. Linha do Tempo Técnica (Para Engenharia).
3. Causa Raiz (Os 5 Porquês).
4. Plano de Ação (Correção Imediata + Prevenção de Recorrência).

Foco: Cultura "Blameless" (Foco no processo, não na pessoa).
```
